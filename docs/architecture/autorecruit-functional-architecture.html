招聘自动化，
不只是一条抓取链路

AutoRecruit 是一个 CLI-first、本地优先 的招聘运营系统：以统一业务模式为入口， 通过证据驱动的状态转换与串行任务队列编排四个平台自动化，并把普通抓取、人才地图、Boss 专属操作与 RAG 知识链路隔离管理。

五层架构，一套运行语义

系统的核心不是页面 selector，而是“业务模式 → 受控编排 → 领域工作流 → 平台语义动作 → 权威事实”的分层。每一层都有明确的输入、失败语义和数据责任。

02 · Product domains

七个功能域，各有生命周期

普通抓取是主干，但不是所有能力的“父流程”。订阅管理、Talent Mapping、RAG 问答和 Boss 独立操作都通过模式隔离，避免把副作用带入不相关的数据域。

DOMAIN 01 · CORE

普通候选抓取与评分

从岗位/JD 与搜索来源出发，完成平台搜索、候选列表读取、身份核验、简历保存、seen、模型评分、结果路由、报告与邮件。支持单岗、jobs-file 批量以及按固定顺序运行的 all。

resume-capturebatchsaved / directscorereportemail
DOMAIN 02

搜索资产与订阅管理

维护筛选 catalog、应用层输入和不可变 revision 条件集；订阅管理只验证条件与结果，可显式保存，但不打开候选详情、不写 seen。

filter catalogcondition setsubscription.manage
DOMAIN 03 · ISOLATED

Talent Mapping

版本化计划驱动 51job、Liepin、Zhilian 的市场扫描与受控详情补全，写 observation/checkpoint，生成公司岗位矩阵、覆盖、变化与导出；实体关联和模型分类必须人工审核。

planscanenrichobservationreviewchange report
DOMAIN 04 · BOSS EXTENSION

Boss 直猎邦 Pro

一部分作为普通抓取的显式第 4 阶段，另一部分保持 Boss-only：推荐/深搜、精确打招呼、原子会话、未读自动审查、职位/JD 同步。高层搜索要求非空关键词并只最终提交一次；所有变更动作以稳定 ID、确认和 durable receipt 防止重复执行。

DOMAIN 05

RAG 知识与质量闭环

JD 和经验证的招聘方事实进入本地 JSONL，经过分块、嵌入与混合检索回答问题；证据不足时明确 no-answer。Qdrant 只是可重建加速层。

DOMAIN 06

运营控制台与助手

React 页面读取本地 HTTP API，集中展示健康度、任务、岗位、候选人、Mapping、Boss、自动化与知识运维；助手只产草稿，不执行任意命令。

03 · Capture pipeline

普通抓取：九步受控流水线

这是最完整的写状态链路。关键点不是“抓到了多少”，而是每一步都保留身份、deadline 与落盘证据，失败时明确哪些状态已经成立、哪些仍可重试。

01模式与输入解析

校验 mode-id、平台、single/batch、JD 与搜索来源组合。

operation-modes · index
02岗位事实复用

新 jobKey 解析 JD；复跑复用平台隔离的 jd.json 与保存设置。

parsers · JobStore
03全局只读预检

all 在任何浏览器动作前校验平台岗位、条件集与筛选输入。

normalizers · preflight
04会话与认证

加载平台 storage state，复用有头浏览器；失效时给出刷新路径。

browser/session
05搜索与条件核验

saved 精确选择订阅；direct 完整应用条件。Boss 空关键词在页面变更前拒绝，非空条件只最终提交一次。

search · platform actions
06候选列表与去重

读取稳定列表/明确空态，以本地 seen 过滤已成功捕获候选。

extractCandidateList
07详情身份与捕获

开详情前后复核身份；完成必要平台交付后保存结构化简历。

open · verify · parse · close
08seen、评分与路由

成功捕获先写 seen，再评分；评分失败落失败产物且不回滚。

scores · routing outbox
09运行、报告与邮件

写轻量 RunResult，导出 Markdown，并按显式/保存设置交付。

results · exports · SMTP
明确空结果 = 成功

平台给出可验证的 0 候选证据时，本轮成功结束，不伪装成提取失败。

捕获前失败 = 可重试

详情打开、身份、转发或解析未完成时，不写 seen，候选保留到下一轮。

捕获后评分失败 ≠ 回滚

简历已成功保存即成为 seen；评分失败单独落失败 artifact。

不明确结果 ≠ 自动重试

外部点击已可能派发但结果证据不完整时停止并保留诊断，不用第二次动作猜测第一次是否成功。

05 · Platform boundary

三核平台 + 一个显式扩展

PlatformAdapter 统一业务输入输出，但不抹平平台差异。每个平台动作自己拥有 selector、兼容 fallback、节奏、就绪判断和后置条件。

01 · 51job 02 · Liepin 03 · Zhilian 04 · Boss（includeBoss）
CORE / 01

前程无忧

51job · 默认主流程
  • 订阅卡片或直接人才搜索
  • 默认按“我已看”策略校准结果
  • 只读取推荐分界前的主结果列表
  • 详情通常是独立页面生命周期
优势：订阅入口身份和结果 generation 验证较完整。
CORE / 02

猎聘

liepin · 默认主流程
  • 快捷搜索或直接关键词搜索
  • 始终使用有头浏览器并支持复用
  • 默认“隐藏已查看”
  • 新增候选可先转发常用联系人
捕获规则：转发失败不解析、不写 seen，详情保留检查。
CORE / 03

智联招聘

zhilian · 默认主流程
  • 快捷搜索标签或直接搜索
  • 默认“未看过”，不改动“未聊过”
  • 简历详情位于当前页 modal
  • 普通抓取独立复制分享链接交付
边界：Talent Mapping 只读简历，不触发分享/交付动作。
EXTENSION / 04

Boss 直猎邦

boss · 显式 opt-in
  • 普通抓取/批量/订阅可作为第 4 阶段
  • saved 需要完整原生订阅身份
  • 最终搜索拒绝空关键词并要求一次可观察结果周期
  • 另有独立人才、会话、自动沟通、职位同步
安全：非提交恢复可精确清空关键词；高层空搜索在页面变更前失败。普通 all 不会隐式触发 Boss 专属联系动作。

06 · Data architecture

本地事实优先，索引只是加速层

普通岗位、Talent Mapping、Boss 回执和运行队列各自拥有清晰目录。平台隔离是第一维度；跨平台同名岗位与同名候选都不会自动合并。

权威目录树

省略了动态文件名，但保留生命周期边界。

▾data/本地事实根
├<platform>/jobs/<jobKey>/JD · resumes · seen · scores · results · rag
├<platform>/filter-catalog/筛选事实与应用选项
├talent-mapping/<mappingKey>/observations · runs · views · exports
├boss/chat-review/自动审查设置、状态与运行
├boss/chat-operations/intent durable receipts
├boss/job-sync/职位快照与同步运行
└runtime/raw tasks/schedules · safe views · rounds · leases
•storage-state*.json平台隔离登录态
JSON / JSONL 是 source of truth

四条数据原则

这些原则决定了失败恢复、审计和后续扩展方式。

P1
平台隔离优先

普通岗位路径从 platform 开始；关键词相同也不能跨平台复用 job record。

P2
raw / safe / executable 分离

历史或畸形数据保持原始证据；读取投影去敏且可渲染，只有完整校验后才产生可执行模型。

P3
写入与副作用有闭合证据

seen、outbox、receipt、lease 与 revision 可回溯；身份或外部结果不明确时不自动重复动作。

P4
独立事实保留，派生索引可重建

Mapping、Boss 与 RAG 保留各自本地权威事实；Qdrant 等外部索引永远不成为唯一副本。

07 · Console & control plane

前端是运营读写面，不是第二套业务内核

React 不维护自己的模式语义；它从服务端读取目录，通过 HTTP normalizer 与 TaskQueue 进入同一 CLI 主编排。ReadModel 直接投影本地事实供页面查看。

08 · Architecture assessment

当前架构：执行所有权已收敛，运营边界仍显式

以下判断来自当前代码、模式目录、路由、作用域文档与长期项目说明。它们不是实施计划，而是理解系统演进位置的“架构体检”。

A+

产品语义有单一目录

src/operation-modes.ts 把 ID、标签、task kind、search source 和 surface 统一起来，显著降低 CLI、助手和前端各说各话的风险。

A

数据恢复与审计能力强

本地 JSON/JSONL 权威；raw/safe/executable 分离、原子写、revision、outbox、receipt、lease 和 run artifact 让历史坏数据与“做过什么”都可离线复盘。

A

危险外部动作受约束

身份在动作前重验，Boss 变更使用 intent ID，助手先草稿再确认；外部结果不明确时不自动重复动作，平台 action 继承 caller deadline 与连续指针。

✓

入口与捕获执行 owner 已分离

src/index.ts 只保留 CLI 规范化、公共平台选择、依赖装配和显式分派；jobs-file 解释、捕获配置/事务归属 src/mode-runners/，候选生命周期、outbox、评分路由与运行结果归属 src/capture-engine.ts。

✓

页面动作所有权已收口

51job 平台控件已迁出 browser/；Liepin/Zhilian 多域 internal-page-actions 已删除；Boss 普通搜索已分为 navigation、search/submit、filter、search entry、candidate、detail 和 post-open owner，且 search/filter 无双向依赖。

✓

调度合同与安全读取已收口

循环资格由共享 inspector/runtime guard 定义；历史 null、未知或 legacy 模板通过 safe view 保持 list/detail 可读并暂停，GET 只派生诊断不改 raw。创建、恢复、控制和入队前均 fail closed，最终 gate 重读快照。

✓

领域隔离方向正确

Talent Mapping、RAG 与 Boss durable receipt 没有被强塞进普通岗位流水线，各自拥有事实模型与 read model，后续更容易独立演进。

✓

本地控制台暴露边界已加固

loopback 保持本地兼容；非 loopback 必须同时配置 Bearer token 和精确 Origin allowlist，CORS 不再通配且 token 恒定时间比较。它仍明确不是多租户 SaaS/Auth Gateway。

→

剩余验收边界

四平台登录态/只读主页已通过真实 canary，Boss 当前列表完成脱敏解析，空关键词负向 canary 证明前置拒绝且 URL、状态与资源计数不变。候选详情、联系/转发、保存订阅、邮件以及非 loopback 部署仍需独立授权与回滚边界。
